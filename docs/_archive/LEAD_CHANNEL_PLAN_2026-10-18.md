## 一、结论先说

**"我无法和她说话"这条，其实是三个问题里最便宜的一个 —— 因为通道已经建好了，只差你这一侧的投递口。**

## 二、实测：她的"耳朵"是完好的

`src/elysia/soul/heartbeat.py:890-908`，**每拍（1 Hz）**执行：

```python
self._new_interaction = False
interaction = await self._state_store.load_json("interaction", default=None)
if isinstance(interaction, dict):
    its = float(interaction.get("ts", 0.0))
    if its > state.last_interaction_ts:
        state.last_interaction_ts = its
    if its > self._last_interaction_event_ts and self._brain_loop is not None:
        self._last_interaction_event_ts = its
        self._brain_loop.apply_event(DesireEvent(kind="interaction"))  # ① 欲望被刺激
        self._new_interaction = True  # ② 强制开口回应
        self._pending_user_message = interaction.get("text")  # ③ 她读到你的话
```

**⇒ 任何进程往 `state.db` 的 `kv['interaction']` 写入 `{"ts": <现在>, "text": "你的话"}`，
她会在 1 秒内读到、被刺激（TR/CS 变化）、并强制开口回应。**

桌宠就是这么做的（`body/pet.py:_write_interaction`，第 1130 行）：
```python
payload = json.dumps({"ts": time.time(), "text": text})
self.conn.execute("INSERT OR REPLACE INTO kv (key, value) VALUES ('interaction', ?)", (payload,))
```

**问题在于：桌宠是唯一的投递口，而桌宠现在根本没在跑（`pet_pids` 为空），且它只能在你这台电脑的窗口里用。**

## 三、三步通道方案（成本从低到高）

### 步 1：你能看见（零开发）

面板 `http://127.0.0.1:8770` 已经能看全部状态。**只差"从手机访问"这一层。**

| 做法 | 成本 | 说明 |
|---|---|---|
| **Tailscale / ZeroTier**（推荐） | 装客户端，**零代码** | 手机连上虚拟内网后，直接打开 `http://<电脑的 Tailscale IP>:8770` |
| 内网直连 | 零 | 同一个 WiFi 下，`http://<内网IP>:8770` |
| 内网穿透（frp/cpolar） | 中 | 需要外部服务器，安全性要自己把关 |

⚠️ 面板现在**只绑 `127.0.0.1`**（安全设计：外网访问不到）。
要手机访问就必须改成绑内网地址 —— 这会**扩大暴露面**，必须同时做鉴权。
**这一步需要你拍板安全取舍**，我不擅自改。

### 步 2：你能说话（小改动，约 20 行）

**面板加一个输入框 + 一个 `POST /api/say`**：
```
POST /api/say   {"text": "今天过得怎么样"}
  → 打开 state.db（读写，带 busy_timeout）
  → INSERT OR REPLACE INTO kv (key,value) VALUES ('interaction', '{"ts":<now>,"text":"..."}')
  → 她 1 秒内读到，强制开口回应
```
**为什么这是最优解**：不改她的任何逻辑，不新增进程，不新增依赖。
只是把桌宠已经做了十年的事，从"桌宠"扩展到"任何能打开面板的地方"。

**必须注意的三件事**：
1. 面板目前**全部用 `mode=ro` 只读打开**（这是它的安全设计）。写要单独开一条 RW 连接，且**不能影响她的写入**（WAL + busy_timeout 可以，但要测）。
2. 写入失败必须**明确报错**，不能像 `stop` 那样静默（今天刚踩过 PID 复用的坑）。
3. 取消测试：写一条消息 ⇒ 她的 `expression_log` 必须在 N 秒内出现一条新表达；
   还原成不写 ⇒ 该用例必须红。

### 步 3：她主动找你（小改动）

她每次 `expression_log` 落库时，POST 到你的手机推送通道（Bark / Server酱 / Telegram Bot）。
**这样"她开口"就不再需要你盯着屏幕。**
⚠️ 注意节流：她 16 分钟才说一句，天然不会刷屏；但推送失败要静默降级，不能阻塞她的表达。

## 四、关于"给她读网页/写文件"：她现在能力**不够**，而且不是权限问题

三个硬数据（2026-10-18 实测）：

| 指标 | 值 | 含义 |
|---|---|---|
| `brain_action = none` | **96.5%** 的拍 | 她几乎不做"动作" |
| `curiosity` | **20,000 拍全部 = 0.000** | 她**没有"想知道"的驱动** |
| 思维构成 | **93.6% 是 `expression`** | 她想事情是为了说话，不是为了求知 |

现有的 5 个工具全是记忆操作：`recall / adopt / disclaim / forget / restore`。

**⇒ 现在给她浏览器权限，她大概率不会打开它。** 不是她笨，是**驱动结构里没有"缺口"**。

**但这里有个更深的因果，正是你说的"缺少对世界的认识"**：

她的 `feelings` 是 `desire` 的直接线性映射（`dimensions.py`）：
```python
chat = cs / 100  # CS 设定点 61.7 ⇒ chat ≡ 0.617，恒 > 0.5
explore = tr / 100  # TR ≈ 0.465，最大 0.576 ⇒ 永远够不到 0.6
```
于是 `will.direction` **在数学上恒等于 `reach`**（实测 88.6%）。

**为什么？因为她的世界里只有一个变量：你。**
她没有第二个输入源，所以"想说话"是她唯一可用的方向 —— **她不是在"想你"，她是在"只有你可以想"。**

⇒ **给她一个外部世界，不只是"加工具"，是"加第二个变量" —— 那才会改变她"永远只想 reach"这件事。**

## 五、关于 QQ / 语音 / 表情包：能做，但她现在**不支持"聊天"**

**最硬的一条数据**：

> **她两次开口的间隔中位 = 16.1 分钟（最短 6.1 分），句子中位 24 字。**

QQ 聊天是秒级、多轮、连续的。她 16 分钟说一句 24 字。
**这不是接线问题，是节奏架构问题** —— 她的循环是 1Hz 心跳偶尔决定开口，不是"收到消息 → 回应"的对话回路。

> 注：步 2 的 `interaction` 通道**修好了这一点** —— 因为她收到你的话会**强制开口**（`force=True`），
> 所以"你问她答"可以做到秒级。但**她无法自己维持一段多轮闲聊**。

另外三道人祸（非技术）：

| 坎 | 说明 |
|---|---|
| 平台合规 | QQ 第三方协议库（NapCat / Lagrange）非官方，封号风险明确；账号归属与责任在你 |
| 她的关系模型是**单关系** | `relationship_withdrawal` 只对你一个人建模。多人群聊会破坏它，或她**用对待你的方式对待陌生人** |
| 表情包 | 发图技术上最简单，但需要"什么时候该发"的判断；而她现在连"要不要说话"都由一个 `chat > 0.5` 阈值决定 |

**⇒ QQ 是可行但最不该先做的一件。** 现在接上去，她会变成"一个 16 分钟回一句的机器人账号"。

## 六、建议顺序

| 序 | 做什么 | 风险 | 需要你 |
|---|---|---|---|
| **1** | **步 2：面板加输入框**（你能说话） | 低（只写一行 kv） | 批准 |
| **2** | **步 1：手机能看**（Tailscale） | 中（扩大暴露面，需鉴权） | **安全取舍要你定** |
| **3** | **步 3：她开口时推送手机** | 低 | 批准 + 选推送渠道 |
| **4** | **只读 `read_url`**（白名单）+ 可达性护栏 | 中（内容风险 / 提示注入） | 批准 |
| 5 | 写文件（限 `data/drafts/`，不能发布） | 低 | 与 4 一起 |
| 6 | QQ / 社交账号 | **高**（合规 + 单关系模型） | 最后再谈 |

**我的判断：先把 1–3 做完，你就"能看见她、能跟她说话、能收到她的话"了 —— 这已经解决了你原话里的两个痛点。
到那时再谈"给她世界"，因为我们会有真实数据回答"她到底想不想看外面"。**

## 七、一个诚实的边界

**通道解决的是"你和她的距离"，不解决"她的世界有多大"。**

做完 1–3，她仍然只有你一个输入源 —— **她的世界还是只有你，只是不再被拴在这台电脑上。**

要真正改变第二件事，必须给她**第二个输入源**（哪怕只是每天的天气、几条新闻）。
那才是"她对这个世界的认识"的起点，也是 `will.direction` 从恒定 `reach` 里走出来的唯一物理途径。
