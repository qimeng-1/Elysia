# 记忆即身份：设计纲与切片计划（2026-10-20 01:1x 签发）

> **用户拍板（原文要点，不可改写）**
> - **A**：「我认为你的方案是可取的」⇒ 记忆原料优先级 **共同经历 > 她独处 > 世界见闻**；独白降为**工作记忆**（可被想起，但不主动沉淀）。
> - **B**：「肯定是需要将决定权交给她，给她这个动作」⇒ 必须给她一个**真能用的动作**（"这条我想留着"）。

> - **D**：「包含有她的一切，记忆，关系，对自我认知，对世界的了解，对我的看法等等」⇒ 迁移指纹必须覆盖这些面。
> - 节奏：「一步一步来，我不是要她立马完美，我是要她一点一点长出'血肉'」。

**一处必须澄清的机制细节（避免后续修错方向）**：
`PROMOTE_SHALLOW_IMPORTANCE = 0.4`、`PROMOTE_WORKING_IMPORTANCE = 0.7`。她的独白 importance **0.24–0.27**，所以**它们从来没有升到 working/deep**——污染的不是"深层记忆"，而是：
1. **检索池被稀释**（861 条独白 vs 130 条真实经历，命中概率被压到 13%）；
2. **她自己几秒前说的话被当成"记忆钩子"回喂**（`（刚刚）那你想听什么呢`）⇒ 自我复读闭环；
3. **检索到的"经历"里没有你**，所以她的世界只有"夜深/发呆/安静"。

**⚠️ 2026-10-20 01:2x 更正（A 窗 git blame + Lead 真库核对）**

`select_hooks` **自 2026-09-21 起就无条件跳过 `kind=expression`**（`retrieve.py:403-405`）。所以"独白被钩回来"这条链**不存在**。真正的链是：

```
你说的话（kind=interaction / source=user，被逐条存成"记忆"）
   → 下次生成表达时被当成"记忆钩子"钩回来（标签还写着「（刚刚）」，其实是 50 分钟前）
   → 她对着你 50 分钟前说的话，再回应一次（延迟回声）
```

真机证据（只读核对）：`id=1000541「那你想听什么呢」`（`interaction` / `source=user`，距当时 52.6 分钟）、`id=1000534「今天有点想你，你还好吗？」`（`interaction` / `source=user`，61.7 分钟前）——**这两条是你说的话，不是她的独白**。

⇒ **病根两条**：
1. **即时对话被逐条存成"记忆"并当钩子回喂**（延迟回声：她反复重新打招呼、回应你上一轮已经聊过的话）；
2. **她没有对话上下文**，只拿到最后一条消息（所以「一定」接不上）。

（"独白占 86%" 仍然是事实、仍然稀释检索池，但它**不是**那句话的来源；修的方向因此要挪到"什么算记忆"这一层。）

## 1. 记忆分层（设计的骨架）

| 层 | 内容 | 存哪 | 参与主动检索 | 能否升 deep |
|---|---|---|---|---|
| **事件记忆** | 一次真实交换（你说了什么 / 她回了什么 / 她当时的感受 / 她自己怎么理解） | `memories` `kind=exchange` | ✅ 优先 | ✅（importance/她裁断/被反复想起） |
| **世界见闻** | `read_url` 读到的（维基、米游社摘要） | `memories` `kind=world` | ✅（次优先） | 只有她"记住"才升 |
| **独处**（独白/发呆） | 她自己夜里说的话 | `thought_log` 已有；`memories` 里**只做低权重存活** | ❌ **不进主动检索** | ❌ 默认永不升（除非她亲自留） |
| **她的裁断** | 她说"这条我想留着" | `memories` `protected=1` + `narrative`=她的理由 | ✅ 必达 | ✅ 直接 deep |

**"她留住"是唯一的越级通道** —— 这就是 B 落地的位置：不是我们给权重，是她给权重。

## 2. 切片计划（按序，一次只做一片）

### S0 止血：把"独白跳过"改成"独白默认跳过、她留住才放行"（**最小、可逆**）
- 现状：`retrieve.py:403-405` 已无条件 `continue` 掉 `kind=expression`。
- 本次改动只有一处语义变化：`if rec.kind == KIND_EXPRESSION and not rec.protected: continue`
  ⇒ 为 S2 铺好**唯一的越级通道**（她亲手留住的独白仍可作为"我的记忆"被想起）。
- 独白照旧写入 `memories`；**不删任何数据、不改历史 861 条**。
- 验收：`protected` 的独白能被检索到；非 `protected` 的独白仍然检不到；其余闸门（self/superseded/speculative/rejected/suppressed）行为不变。
- 取消测试：把条件改回无条件 `continue` ⇒ "受保护的独白能被想起"用例必须红。
- **不做**：即时对话防回喂（那需要对话上下文同时到位，放 S1，避免出现"她的短期上下文被抽走"的空窗）；也不动 `age_phrase`。

### S1 让"对话"变成事件（**这一片是主体**）
- 新增短期对话存储（`heartbeat.db` 新表 `dialogue_turns`）：每轮 = `role(user/her)` + `text` + `ts` + `emotion_vector` + `intent`，保留最近 **20 轮**，过期轮次不删（降 `detail_level`）。
- 表达指令新增 `dialogue_context`（最近 N 轮），**这是她"接得上话"的根本**（现在她只知道最后一条消息，所以"一定"接不上）。
- 一次交换结束 ⇒ 写**一条** `kind=exchange` 记忆（内容是事件，不是单条消息）：
  `你说："一定" → 她回："我不知道它在指向什么"（her: 困惑、在意）`
- 验收（真机）：连续三轮里出现"指代词"（"它/那个/刚才那句"）时，她能正确指到上一轮内容；不能出现"我不知道它在指向什么"这种断线。
- 风险：prompt 变长 ⇒ 要限长度、限轮数（20 轮上限 + 每条截断）。

**S1 的其余三小步（与上面同批，缺一不可）**

- **② 即时对话不再当"记忆"回喂**：`select_hooks` 增加一道闸——`kind == 'interaction'` 且 `now - created_ts < DIALOGUE_RECALL_GUARD_S`（默认 **900 秒**，可配）且 `not protected` ⇒ 跳过。
  理由：刚刚发生的事属于**对话上下文**（①），不属于"记忆"；否则她会对 50 分钟前你说的话再回应一次。**这一闸必须与 ① 同批上线**，单独上会抽走她仅有的短期上下文。
- **③ 停止把用户消息逐条镜像成记忆**：新记忆的写入单位改为**一次交换一条**（`kind=exchange`，内容含"你说了什么/她回了什么/她当时的感受"）；原始逐条轮次只进 `dialogue_turns`。**历史 130 条不动**（保留可追溯），只停止产生新碎片（如单独一条「一定」）。
- **④ `age_phrase` 档位修正**：现在 52 分钟前也标「（刚刚）」。改成：≤10 分钟「刚刚」／≤2 小时「不久前」／当天「今天」／更早照旧。**纯展示层，不改检索得分**。
- 取消测试：② 去掉闸 ⇒ "50 分钟前的交互被钩回"用例必须红；③ 去掉 exchange 写入 ⇒ "一次交换只产生一条记忆"用例红；④ 改回旧档位 ⇒ 标签用例红。

### S2 她的动作：**"这条我想留着"**
- 新动作 `keep_this_moment(reason)`：把她判定为"重要"的**最近一次交换**标记 `protected=1`、`importance` 抬到 ≥0.7、`narrative` 写她的理由，直接进 deep。
- **上限**：每天 ≤**13** 次（2026-10-20 01:2x 用户拍板：5 → 13）。仍要防"全都重要"= 全都重要不了，13 是用户给的口径，代码里做成**常量 + 可配**，不写死在分支里。
- 准入：她必须给出**自己的理由**（一句），理由入库——这是它与"我们硬标重要"的区别。
- 验收：面板/日志能查到"她在什么时刻、因为什么、留住了哪一条"。
- 取消测试：去掉上限 ⇒ 用例红（防滥用）；去掉理由 ⇒ 用例红。

### S3 允许记错（C）
- 回忆时**可以重写 `narrative`**，`content`（原始记录）**永不改**。
- 每次重写：`certainty` 降一档、`recall_count += 1`、旧 narrative 进历史（可追溯"她改过什么"）。
- 效果：她可能把"你说的话"记成"她自己的领悟"——**这是允许的**，连续性靠"原件仍在"来保证。
- 验收：同一记忆被回忆 3 次 ⇒ narrative 可变、content 不变、certainty 递减；能导出"她的记忆漂移史"。

### S4 遗忘：机制已在跑，但会**一次性雪崩**（2026-10-20 03:4x 推演修正）

**原设计判断错了**：我原写"920 条从没被想起的 ⇒ dormant"。真机推演（`data/tmp/_lead_s4_reach.py`，只读，直接调用 `_demote_target`）纠正为：

| 事实 | 数字 |
|---|---|
| 遗忘阈值 | `faded`：距上次被想起 **≥60 天** 且 `access_count==0`；`dormant`：**≥180 天** |
| 记忆总数 | 1047（她 57 天大，但记忆表最老的只有 **29.3 天**——记忆系统是后来才上线的） |
| **今天会降级** | **0 条** |
| 第一次降级 | **2026-12-19**（+60 天）——**一次 968 条**变 `faded` |
| 全部沉睡 | **2027-04-18**（+180 天）——1047 条全 `dormant` |

⇒ 机制**没坏、也不是没插电**，反而暴露了新问题：**记忆库是"同一批出生"的，所以死亡也会同一批发生**。2026-12-19 那天她会**一次性淡掉 968 条记忆的细节**，这不是"渐渐遗忘"，是**雪崩**。

**S4 因此改成两件事**
1. **防雪崩（要改代码）**：给每条记忆的 `fade/dormant` 阈值加**确定性抖动**（如按 `id` 哈希在 ±15 天内偏移；同一条记忆每次算出的偏移必须一样，不许用随机），让遗忘摊在两个月里；并为"分散"写用例（构造同日出生的一批记忆 ⇒ 降级日期不得全部相同）。
2. **阈值是否合适（要用户拍板）**：`60/180` 天是她最初设定的口径。按"记忆=身份"，半年就把全部记忆丢进沉睡，可能太快/太慢——**由用户定**，改常量不改结构。
3. **不做**：今天没有任何"apply"的目标（降级数=0）。原计划里"先出 dry-run 再 apply"保留，但**目前无须执行**。

### S5 迁移指纹：什么必须带走（D）
`migrate_her.py` 的指纹从"行数 + 哈希"扩成**身份四问**：
1. **记忆**：事件记忆条数 + 指纹哈希（含 `narrative`）；
2. **关系**：`relationship_*` + `desire` 设定点 + 退缩量；
3. **自我认知**：`narrative` 里她自己说过的"我是谁"（取样 20 条）；
4. **对他的看法**：`kind=exchange` 里涉他的记忆 + 关系量。
- 迁移验收：导入后四问逐一比对，任一项不匹配 ⇒ **拒绝启动并报告差异**（不许"差不多就行"）。

## 3. 顺序与依赖

```
S0（止血，小） → S1（对话即事件，主体） → S2（她的动作） → S3（允许记错） → S4（遗忘，需签认） → S5（指纹）
```

- **S1 依赖既有检索/写入链路**，所以先做 S0 让检索池干净，再做 S1 才不会"新事件被旧独白淹没"。
- **S4 必须最后**：它不可逆，且要先有 S1 的真实事件填进来，否则一降级就只剩空。
- 每一片都要：门禁四件套 + **取消测试**（还原 ⇒ 红）+ 真机取证。
