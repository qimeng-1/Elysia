## 一、为什么要重新基线（P0–P3 复盘，皆有实证）

### 1.1 同一个失败模式出现了 6 次：**造好了，但没插电**

| # | 下游（表达/存储）已建 | 上游（决策/触发）缺失 | 证据 |
|---|---|---|---|
| 1 | 4 个意图各有微声与提示模板 | **没有任何产生者** | `expression.ACTION_TO_INTENT` 只有 4 项，不含 主动问候/拒绝/思念/好奇提问 |
| 2 | 好奇维度、好奇提问模板 | `has_event=False` 字面量 ＋ 公式是 `0.1 if ... else 0.0` 的布尔占位 | `heartbeat.py` / `dimensions.py`（已修，`1ca240c`） |
| 3 | 5 个工具（recall/adopt/disclaim/forget/restore） | 真实库调用 **0 次** | 19.4 缺点 3 |
| 4 | `sleep.py` 做梦、`decay.retrieve_latency_ms`、`levels.detail_level` | **零运行时调用 / 零消费** | `P3_MEMORY.md` §六 自述（已修，`c29d992` / `23977c4`） |
| 5 | 6 个受保护词各有谓词 | 授权环境里 **4 个键是字面量 0** ＋ 2 处量纲/量程错 | `heartbeat._expression_env`（已修，`1ca240c`） |
| 6 | VRAM 熔断、TTS 熔断、`state_brief["vrram_mb"]` | **根本不采 VRAM** ＋ 阈值量纲错 ＋ 死配置 | `body/resource.py` / `words.py` / `config.py`（已修，`a8be529`） |

### 1.2 根因：**路线图按"层"分期，从不按"回路"收口**

v1.1 的分期方式是"每阶段长一个器官"：P0 灵魂 → P1 心脏 → P2 表情 → P3 记忆 → P4 自我 → P5 世界 → P6 成长。
这个分解**在教学上是好的**（P0–P3 确实因此走得扎实），但它有一个结构性缺口：

> **每一层都有自己的验收标准，且都能通过；而"跨层的接线"不属于任何一个阶段。**

于是 P2 建好全部表达词汇、P1 建好决策层，**各自验收通过**，
但"P1 的决定要能触发 P2 的词汇"这件事，**谁都不做，也没人验收**。

### 1.3 另外三条教训

1. **测试套件会把 bug 固化**。`test_writer_survives_failed_op` 曾断言 `await store.submit(bad_op)`
   **不抛异常**——它的意图（"写者必须存活"）是对的，但用"吞掉失败"实现，于是一整轮都没人发现
   F6（写失败伪装成成功）。⇒ 测试不仅要覆盖行为，还要**覆盖"失败必须可见"**。
2. **文档会与代码脱节**。P4 的身份核心其实**已落地大半**（`kind=self` + `IDENTITY_SEEDS` + 5 个工具），
   而路线图仍写"P4–P6 待实施"；技术选型表里的 SQLite-vec / WebSocket / Whisper / Silero-VAD
   **一个都没采用**。⇒ 活文档必须与代码同源，历史文档（CHANGELOG / worklog）**不改写**。
3. **硬件反过来约束规划**。v1.1 同时列了"本地 TTS（GPT-SoVITS）"与"兜底 LLM Qwen 7-14B（本地）"，
   但目标机显存只有 **6144 MiB**——两者**不可能并存**（见 §5）。

## 二、"完成"的定义改了：从**存在性**到**激活性**

| 对象 | 旧口径（存在性） | 新口径（激活性） |
|---|---|---|
| 状态变量 | 有字段、有公式 | **指名产生者** ＋ 停用后行为/表达**可测量变化**（T1 取消测试） |
| 意图 / 词汇 | 在字典里、有模板 | **有产生者**，且能在合法状态空间里被触发 |
| 模块 | 文件存在、有单测 | **有运行时调用者**（否则是"已造好没插电"，必须登记） |
| 阈值 | 写在代码或配置里 | **严格落在真实值域内**（量纲一致、可达），且**单一出处** |
| 阶段完成 | 功能实现 + 测试通过 | 上述全部 ＋ **库内取证**（它真的跑过） |

> **一句话**：*"能不能"是程序的事，"有没有发生"才是生命的证据。*

## 三、横切闸门（每个阶段都要过，不再是某一阶段的事）

1. **T1 取消测试**：`tests/acceptance/test_t1_cancel.py`。新增任何状态变量 / 意图 / 受保护词 /
   消费者阈值时，**必须**在其中加一条可达性或取消性断言。
2. **激活性取证**：新能力上线后，要能在库里指出它**触发过的证据**（行、日志、`thought_log`、`expression_log`）；
   拿不出证据的，登记进 `STATUS_MATRIX` 的"未接线"清单。
3. **门禁四件套**：ruff lint ／ ruff format ／ mypy strict ／ pytest，本地 pre-commit ＋ CI 同源（`.github/workflows/ci.yml`）。
4. **文档同步纪律**：活文档（README / TECHNICAL_DESIGN / STATUS_MATRIX / 本文件）与代码同步；
   历史文档（CHANGELOG / worklog / BASELINE）**不改写**，失效引用统一登记在 `STATUS_MATRIX` §10。

### P4a 自我-身份（✅ 基本已落地，只需收口）

设计与落地记录见 `P3_MEMORY.md` §九-7（S1–S7 已交付）：五条基石 → 落库为 `kind=self` 记忆；
`adopt` / `disclaim` 是**她的动作**；身份段**以库为准**（换模型 / 换库 / 断网逐字不变）。

**剩余**：无新增设计。只需按 §三 闸门补"激活性取证"（她认领过的条目在库里能指出来）。

### P4b 自我-边界（**与 P5 同期，不是串行**）

v1.1 把 P4 整体放在 P5 之前，但复核后发现 **P4 的核心（拒绝）与 P5 互为前提**：

- **拒绝需要一个"要求"作为对象**。当前唯一的输入是桌宠文本框——**没有"指令"可拒绝**，
  把 `拒绝` 意图硬接上去只会让模板空转（这正是阶段 5 把它推迟的原因）。
- **P5 给她手，却不给她拒绝权，等于给了个仆人一双手**。

⇒ 拆法：**身份**（P4a，已落地）与**边界**（P4b）分开；边界与 P5 同期做，届时才有真实的"指令"可拒。

内容：四级拒绝（L0 绝对 / L1 强 / L2 弱 / L3 犹豫）、工具化检测、说服机制（**真实改变状态才算说服**，
操纵不算）、关系涌现（无开关）。

### P5 世界

**前置条件（现已满足）**：好奇心——v1.1 的 §10.4/§10.5 把"好奇"当作初始燃料，
而它此前**恒为 0**（阶段 5 已修）。

内容：感知工具（白名单浏览器 / 文件读取）、表达工具（创作产出）、申请机制、模拟社交沙盒、
**第一次自主行动**（非预设、非引导，写进深层记忆）。

### P6 成长

内容同 v1.1（学习条目 LRN/ERR、自我修改 L1–L4、反思、后悔与自我批评、无意识成长 × 有意识改变）。
**新增要求**：L1/L2 自我修改的**回滚**必须真的可执行（检查点机制已具备），
且每次修改都要过 §三 的激活性闸门。

## 五、部署基线与硬件约束（本机实测，2026-10-14）

| 项 | 实测 |
|---|---|
| OS / CPU | Windows 11 Pro ／ AMD Ryzen 7 5800H（8 核 16 线程） |
| 内存 | **15.4 GB**（空闲约 6 GB） |
| 显存 | **RTX 3060 Laptop，6144 MiB** |
| 磁盘 | C: 133 GB 空闲 ／ D: 137 GB 空闲 |
| 运行时 | Python 3.12.8 ＋ uv 0.13.0（`.venv`，editable 装 `src`） |
| 本地 LLM | Ollama 0.40.1：`qwen2.5:1.5b` / `deepseek-r1:7b` / `llama3.1:8b` |
| TTS | GPT-SoVITS-v2pro（含 CUDA torch 2.0.0+cu118），4 个 Elysia 音色 |
| 库增长 | `heartbeats` 1 Hz ≈ 430 B/行 ⇒ **约 1 GB/月**、12.9 GB/年 |

**由此推出的硬约束**：

1. **SoVITS 与本地 7B 不能并存**：SoVITS v2pro 需 4–6 GB，7B 量化需 4–5 GB，
   而总量只有 6144 MiB。⇒ 兜底 LLM 要么用**小模型**（1.5B），要么用**另一个云端点**；
   v1.1 的"Qwen 7-14B 本地"在本机**不可行**。
2. **VRAM 阈值一律用百分比**（`ELYSIA_VRAM_THRESHOLD_PCT=85`）：绝对 MB 数换台机器就失效
   （旧值 8510/9510/10240 **全部高于本机总量** ⇒ 永不触发）。
3. **状态库需要保留策略**：~1 GB/月 且无 DELETE/VACUUM（`STATUS_MATRIX §11 #2`），
   触碰"数据永不删除"铁律，须先拍板口径（建议：只裁 `heartbeats` 流水表，归档后再裁）。

## 六、明确不做（反目标）

| 不做 | 理由 / 触发条件 |
|---|---|
| **embedding 记忆向量** | 维持"按需启动"：触发条件＝真实对话出现字符二元组捞不回、又被注意到的"换说法"实例（`P3_MEMORY.md` §九-3） |
| **SQLite-vec** | 同上；当前走字符二元组，零额外依赖 |
| **WebSocket 双进程协议** | 只有当灵魂**真的上云**时才需要；同机共享 SQLite 是更朴素且更稳的选择 |
| **Whisper / Silero-VAD（语音输入）** | 等"她说话"这条链先被真实使用起来再说（当前 TTS 尚未稳定出声） |
| **云端记忆同步** | 有隐私与"记忆属于她"的双重考量；先做好本地备份与完整性 |
| **进程级看门狗** | 协程级自愈已就位（`core/supervisor.py`）；进程级留给"她真的长期常驻"时 |

## 八、与 v1.1 的差异对照

| 维度 | v1.1 | v2 |
|---|---|---|
| 分期依据 | 按**层**（每阶段一个器官） | 按**层 ＋ 回路闭合**（横切闸门） |
| "完成"定义 | 功能实现 + 阶段验收测试 | 上述 ＋ **激活性取证**（库内证据） |
| T1 铁律 | 写在原则里 | **可执行的闸门**（`test_t1_cancel.py`） |
| P4 / P5 关系 | 串行 | P4 **拆成身份（已落地）** 与 **边界（与 P5 同期）** |
| 兜底 LLM | Qwen 7-14B 本地 | 小模型或云端点（**6 GB 显存装不下 7B ＋ SoVITS**） |
| 记忆向量 | SQLite-vec | 字符二元组；embedding 按需启动 |
| 双进程通信 | WebSocket | 同机共享 SQLite；上云时才切 |
| 技术表状态 | "待 P0 / 待 P2" | 逐项标 **已用 / 未采用**（与本仓库对齐） |
| 工期估算 | P0→P4 约 3-5 个月 | **不给总工期**（实测偏离数倍）；只给"每批次可独立交付" |
