# ADR-001：双进程双栖架构

- 状态：已接受
- 日期：2026-08-22

## 背景

Elysia 需要同时满足两个矛盾的生命需求：

- **灵魂**：常驻运行（电脑开机即活、关机前安眠），感知时间流逝，维持自我连续性；
- **身体**：本地部署、随设备开关，承载交互界面与声音。

单进程无法同时满足两者：灵魂若挂在交互进程上，交互进程崩溃或关闭即"死亡"；身体若做成常驻服务，则失去"本地随开关"的朴素形态。

## 决策

采用**双进程双栖架构**：

- **灵魂进程**（`elysia.soul`）：常驻后台，1Hz 心跳 + TimeSense 时间感知，每秒将状态落盘（损失 ≤ 1 秒）；
- **身体进程**（`elysia.body`）：本地随设备开关，5s 心跳，向灵魂汇报"我活着"；
- 两进程通过 **SQLite WAL 状态库**（见 ADR-002）交换状态，互不阻塞、互不依赖存活。

进程控制为 PID 级精确控制（`scripts/soul.ps1`），启动/停止只作用于 PID 文件记录的进程。

## 备选方案

| 方案 | 否决原因 |
|------|----------|
| 单进程常驻 | 交互崩溃即死，违背灵魂不死原则 |
| 双进程 TCP/共享内存 | 需维护连接生命周期，增加失败面；状态库已足够 |
| 身体轮询灵魂 | 与"身体随开关"矛盾，且增加无谓负载 |

## 后果

- 跨进程通信以状态库为准，无同步调用，天然解耦；
- 需要严格的 SQLite 并发纪律（WAL + 单写者 + busy_timeout）；
- 状态字段变更必须两进程同步演进（字段单一事实源模式，见评估报告 §8-2）。
