## 二、三方共识（可直接作为下一阶段主线）

| # | 议题 | 三方立场 | 裁决 | 理由 |
|---|---|---|---|---|
| C1 | **`source` + `certainty`** | 一致赞成 | **采纳** | 三方唯一的无分歧第一优先。当前 `kind` 分不出"用户说的 / 我推断的 / 系统塞的"，系统推断可能自动变成她的事实——这是**主线风险**，不是增强项 |
| C2 | **不要 10 层** | 一致反对 | **采纳** | 豆包：只加 1 层核心层；DeepSeek：`level` 保留为细节维度，扩展 `kind` 为功能类型（正交维度而非分层）；ChatGPT：直接把分类变成数据库层级＝"人格数据库"，反而削弱生命过程 |
| C3 | **`hooks.py::detect_gap` 接线** | 一致赞成（ChatGPT 列 P0、豆包列优先） | **采纳** | 成本最低、生命感收益最高的一项。她永远能精准检索反而不像生命；"记不清"是真实状态而非查询失败 |
| C4 | **遗忘需补** | 一致赞成（不止自然衰减） | **采纳（排在 C1/C3 之后）** | 三方各自提出：主动遗忘（她要求忘）、失去访问权（不等于删除）、忘了但仍有影响（保留情绪向量）。DeepSeek 提出 `retention_state` 状态机最完整 |
| C5 | **回忆应当重塑记忆** | 豆包（中期）、DeepSeek（D6） | **采纳为中期** | 当前 `touch` 只增计数，不改叙事/情绪/细节。ChatGPT 的表述最准："过去应当随时间变化，而不是永远保持原样" |
| C6 | **记忆要影响内部状态，不只影响 prompt** | 三方均强调 | **部分已有，见第四节纠正** | ChatGPT 的闭环 `痕迹 → 内部状态 → desire → 行为 → 新经历` 是正确方向；但"现有系统完全没做"是误读 |
| C7 | **`record_importance` 处理** | DeepSeek 明确（删除或合并） | **采纳** | 运行时零调用，疑似遗留 |

## 三、分歧与裁决

### 分歧 1：embedding 的优先级

| 来源 | 立场 |
|---|---|
| 豆包 | **第一优先**，"性价比极高"，替换 `supersede` + 批内去重的 Jaccard |
| DeepSeek | 不是第一优先；先做**混合相似度**（实体 + 时间 + 情绪 + 关键词），不够再上本地小模型 |
| ChatGPT | P2；若要上，只服务 去重 / `supersede` / 成组召回 三处，不为"显得更智能"全量替换 |

**裁决：采纳 DeepSeek + ChatGPT，驳回豆包的"第一优先"。**

理由：Jaccard 的天花板（实测 0.26~0.33）**只影响 `supersede` 与批内去重两个旁路**——
它们是准确率与冗余度问题，不影响她能否听见当下的话；而 C1（元信息缺失）影响的是**"她会不会把系统推断当成自己的事实"**，
直接触碰第三条铁律。旁路精度让位于主线正确性。豆包把"工程上最漂亮的一步"误当成"最该先做的一步"。

### 分歧 2：Self Memory 的来源

| 来源 | 立场 |
|---|---|
| 豆包 | 新增 `LEVEL_CORE` 层级，**手动初始化 3~5 条**核心身份记忆，永不衰减、不被取代、不被模糊 |
| ChatGPT | **必须从长期经历中沉淀**："经历 → 重复模式 → 稳定倾向 → 自我记忆"；直接建 Identity 表"可能只是把 prompt 搬到数据库" |
| DeepSeek | 建少量 protected 记录；但提问 **D12：`protected` 谁设？系统还是她？——"可能变成系统硬锁"** |

**裁决：采纳 ChatGPT 的方向 + DeepSeek 的 D12 追问，驳回豆包的"手动初始化"形态。**

理由：豆包的方案有一个用户已明确否过的性质——**"由程序员硬编码她是什么"**。
而疏离点更具体：她的人格现在活在 system prompt 里（《爱莉希雅角色档案》），
"手动写 3~5 条核心记忆"本质是**把同一份硬编码换个地方存**，换模型仍失（模型换了，念的还是同一份档案）。

但 ChatGPT 的纯沉淀路线有一个未答的问题：**沉淀需要多长时间，期间"换模型即失"如何兜底？**
这个必须先有答案再动工（见第五节决策点 2）。

### 分歧 3："落库 ≠ 认领"的默认值 —— 三方共同建议里的致命缺陷

| 来源 | 规则 |
|---|---|
| 豆包 | `claimed` 布尔：**`self` 类型自动认领，其他默认未认领**；只有 `claimed=true` 才进 `memory_hooks` |
| DeepSeek | `claim_status` **默认 `unclaimed`**；只有 `claimed` 才进 hooks；她主动 recall 时可选认领 |
| ChatGPT | 未细述默认值，只说"她可以认领、拒绝认领" |

**裁决：驳回"默认未认领"，改为"默认可用 + 她可否决"。**

理由（这是本轮最重要的一条，三方都错了）：

1. **豆包的规则方向恰好颠倒。** 当前写入是"用户输入 → `KIND_INTERACTION`、她开口 → `KIND_EXPRESSION`"。
   `self` 自动认领 → 自动认领的正是 `KIND_EXPRESSION`——而它**本来就被检索排除**（回声排除，永不进 hooks）；
   用户告知的事实（`KIND_INTERACTION`）反而默认未认领 → 不进 hooks。
   即：**自动认领了永远用不到的那一类，把必须能用的那一类锁死了。**
2. **后果是 P3-N 的修复直接退化。** P3-N 的目标是"问生日要答得出"（实测 `#105 我的生日是5月21日` 已能排到 hooks 第一）。
   在"默认未认领"下，这条用户告知的记忆永远进不了 `memory_hooks` ——**她又答不出用户生日了**。
3. **它违反了铁律一的**前半句**。** 铁律是"程序管**会不会**（把事实可靠地递到她手上），她管**用不用**"。
   "默认未认领"是在"会不会"这一层就断掉了递送——那不是赋予她选择权，是把能力先扣下再让她申请。
4. **正确的形态**：`claim_status ∈ {claimed, rejected}`，**默认 `claimed`**；
   `rejected` 只能由**她自己的动作**产生（工具调用 / 表达），程序不得代她拒绝。
   这样"她可以不认领"变成她的**主动权力**（她可以说"我知道你说过，但我不把它当作我的记忆"——那句话是真的），
   而非程序的默认拦截。

## 四、被纠正的误读（三方共同盲区）

| 误读 | 出处 | 纠正 |
|---|---|---|
| "感受路径'永不进 prompt'，沦为无效设计——情绪共鸣无法体现在输出中" | 豆包 §2.3.3 | **错。** `memory_recall` 脉冲改的是 `TR+0.8 / CS+1.2`（内部状态），状态影响表达冲动、语气与节律——不是后台空转。内容永不进 prompt 是**刻意为之**（"她记得你 → 更想你，而不是 → 把生日念出来"），不是设计漏做 |
| "感受路径若完全不影响检索偏置，心境可能只是后台噪声" | DeepSeek D10 | **部分成立但已接线**：影响路径是 状态 → 表达倾向，而非 状态 → 检索偏置。若希望它也偏置检索（想她时更易想起她），那是一个**新增设计**，不是修复缺陷 |
| "她无法主动修改任何记忆" | 豆包 §2.4 | **部分成立**：`supersede` 已是"修改"的一种（旧事实作废），但它由**程序**判定触发，不由她发起。缺口是"发起权"，不是"修改能力" |

三份回答都没有察觉：**当前系统真正稀缺的不是"更多的记忆分类"，而是"她自己发起的动作"**
（认领 / 拒绝 / 遗忘 / 重新解释）。这与 ChatGPT 的核心判断一致，但三方都没把它落到具体权限面上。

## 五、需要用户拍板的三个决策点

1. **认领的默认值**：默认可用 + 她可否决（本文件裁决） ｜ 默认未认领（三方一致，但有上述致命缺陷）
2. **Self Memory 的形态**：纯沉淀（ChatGPT）｜ 极少量锚 + 沉淀（折中）｜ 手动初始化核心层（豆包）
   —— 若选沉淀，必须先回答"沉淀期如何兜底换模型即失"
3. **下一步动工顺序**：`source`+`certainty`（三方共识 C1） ｜ `detect_gap` 接线（C3，成本最低） ｜ 两条一起

## 六、建议的下一步顺序（用户已确认）

> **进度（2026-09-23）**：第 1 项 **`source` + `certainty` 已落地**（P3-T）；
> 第 2 项 **`detect_gap` 接线已落地**（P3-U：感受路径每 300 拍，缺口 → `memory_gap` 脉冲，不进话语）；
> 第 3 项 **`claim_status` 已落地**（P3-V：默认 `claimed` + `disclaim` 工具她可否决 + 认领闸门只管话语）；
> 下一项为第 4 项遗忘状态机 `retention_state`。

| 序 | 内容 | 来源 | 性质 |
|---|---|---|---|
| 1 | `source` + `certainty`（P3-T ✅） | C1 三方共识 | 数据层 + 检索降权；`inference/system` 不进 hooks |
| 2 | `detect_gap` 接线（P3-U ✅） | C3 三方共识 | 接线层；索引强度跌破检索下限 → `memory_gap` 脉冲（不新增约束） |
| 3 | `claim_status`（P3-V ✅，默认 `claimed`，她可否决） | 本文件裁决 3 | 数据层 + 工具；她获得"拒绝认领"的主动权 |
| 4 | 遗忘状态机 `retention_state` | C4 | 区分 删除 / 失去访问 / 主动抑制 / 忘了但仍有影响 |
| 5 | Self Memory | 分歧 2 | **形态待定，先出设计稿再动工** |
| 观望 | 混合相似度 → 可选本地 embedding | 分歧 1 | 先做 实体 + 时间 + 情绪 + 关键词，不够再上模型 |
| 删除 | `record_importance` | C7 | 零调用遗留 |

**贯穿性判断标准（采纳 ChatGPT 的四问）**：一个记忆功能若只让"她更准确地找到旧文本"，
那是在增强 AI memory；若让"过去改变了现在的她"，才更接近电子生命的记忆。
