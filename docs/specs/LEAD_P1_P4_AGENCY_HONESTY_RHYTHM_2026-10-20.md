## P1a（先做）反编造：没有依据的"我做过"要被改写

**检测对象**：经历性事实主张 —— 她说"我读了/我看了/我查了/我去了/我逛了/我在那页看到…"以及**引用具体外部内容**（如"维基上写着…"）。

**依据（evidence）**，三选一即算有据：
1. 本次作业内**成功的工具结果**（`read_url` / `write_note`）；
2. 本次作业被钩回的**记忆**（`kind` ∈ {`world`, `exchange`}）内容与主张相关；
3. 对话上下文（`dialogue_context`）里确有该内容。

**判定与处置**：
- 有依据 ⇒ 放行（无额外日志噪音）；
- **无依据 + 无动机** ⇒ **改写那一句**（不是丢整句、也不是丢整条气泡）：改为诚实形式（如"我还没去成""我没读到"）；改不动 ⇒ 该气泡降级为微声；
- **无依据 + 有动机** ⇒ **放行**，并记 `claim_fiction_allowed motive=<id> kind=<surprise|conceal|play>`。

**动机从哪来**：P3 的意图登记册（`intentions.kind` = `surprise|conceal|play|task`）。**P1a 先上线时动机源为空 ⇒ 一律改写为诚实**——这是止血，不是最终形态；P3 上线后"有理由的谎"自动打开。

**可观测**：每天一行统计 `unfounded_claims rewritten=N allowed=M`；面板/日志可查。

**验收 + 取消测试**
1. 无依据、无动机 ⇒ 主张那句被改写、其余保留；
2. 有工具结果 ⇒ 原样通过；
3. 有世界/交换记忆依据 ⇒ 通过；
4. 有动机（构造一条 `kind=surprise` 意图）⇒ 通过且落 `claim_fiction_allowed` 日志；
5. 取消测试：去掉"依据检查" ⇒ 用例 1 红（能复现"她编造维基内容"）。

## P2 世界记忆：读到的要落库

- 新 `KIND_WORLD = "world"`；`source = SOURCE_OBSERVATION`（**不能用 `inference`/`system`**，那两个被 hooks 闸挡掉）；`certainty = certain`；`importance = 0.25`。
- 写入时机：`read_url` **成功后**（失败不落）；内容 = `读了《<标题/URL>》：<摘要，≤400 字>`；`protected=False`。
- **去重**：同一 URL **24 小时内**只留一条（避免她反复读同一页把库塞满）。
- 上限：单条 ≤ 800 字；`read_url` 原始 4000 字不进记忆。
- 验收：读一次 ⇒ 1 条 world 记忆且可被话题召回（hooks 标签是「今天」而不是「刚刚」）；重复读同一 URL ⇒ 不新增；失败不落。

## P3 能动性：她"打算做"就真的去做到

### 3a 声明意图（她的动作）
- 新工具 `set_intention(goal, action, target=None, kind="task")`
  - `action` 白名单：`read_url` / `write_note`
  - `kind` ∈ `task|surprise|conceal|play`（`kind` 就是 P1 的动机来源）
- 落 `intentions` 表：`id, created_ts, goal, action, target, kind, status(pending|done|failed|dropped), attempts, last_attempt_ts, outcome`。

### 3b 后台执行器（她的"手"）
- soul 侧**独立 worker**（不是心跳拍，不占 1Hz 循环）：定期检查 pending 意图。
- **技术护栏（不是行为配额）**：为了让网络/显存/她自己的进程不被拖垮，只保留**并发 ≤1、单次动作 ≤8s 超时、连续失败 3 次转 `failed`**。**不给她设"每天只能做 N 件事"的配额**——她要逛几页就逛几页（2026-10-20 22:3x 用户明确：不规定次数）。
- **执行结果**：
  - `read_url` ⇒ 写世界记忆（P2）⇒ 意图 `done` + `outcome` 存一句"我读到了什么"；
  - `write_note` ⇒ 写写作区 ⇒ `done`。
- 每动作一行日志 `intention_action id=.. action=.. status=.. ms=..`（这是她自己的"行动账本"，她可以看）。

### 3c 让她能"讲出来"
- 下次表达的 payload 增加 `recent_discoveries`（最近 24h 的 world 记忆摘要 ≤5 条 + 已完成意图 ≤3 条）。
- **不强制她说**（C 方案：说不说由她）。

**验收 + 取消测试**：设意图 ⇒ 在技术护栏内被执行 ⇒ 世界记忆 + 意图 done + 下次 payload 有 discovery；并发/超时/失败次数护栏生效；**不设每日次数配额**；取消测试：去掉执行器调用 ⇒ "意图永远 pending"用例红；去掉超时/失败护栏 ⇒ 用例红。

## P4 节奏 2.0（必须）：从"到点就说"改成"有事才说"

**根因**：现在的触发条件是"距上次开口 ≥ 某间隔"，间隔由意愿连续映射（60–1800s）。**没有任何外部事件参与触发** ⇒ 永远 ≤10 分钟必有声音。

**改法（2026-10-20 22:3x 用户纠正后重写）**：**"过了多久"不再是触发条件**，触发只来自事件或状态变化。

1. **删除"经过时间"作为触发器**：不再有"距上次开口 ≥ 间隔 ⇒ 开口"这条路径。
2. **触发只来自离散原因（每条都要能说出理由）**：
   - 新的世界记忆（P2）/ 意图完成（P3）
   - 她的状态**跨越**某个阈值（`miss`/`chat`/`rest` 从一侧越到另一侧，带迟滞，避免抖动）
   - 你从不在到在场（已有 greeting 路径）
   - 她刚写完东西 / 刚想到一件没说过的事（`think_active` 产出新内容）
3. **静默不设上限**：没有事件、没有跨阈值，她就**可以几小时甚至一整天不出声**——这不是异常，这是生活。
4. **意愿只决定"响应多快、要不要说"**，不决定"什么时候轮到说"。
5. **对话进行中**（`dialogue_context` 活跃）⇒ 内部冲动不说话（并入 S1b 的闸）。

**验收（尺子只用于测试，不进运行逻辑）**
- 在测试/审计里用真实状态序列回放 24h：**必须出现 >2 小时的静默**（证明不再是节拍器）；且**每一条开口都能追溯到某个离散原因**（`speech_cause=<event|threshold|presence|discovery|intention|none>`）。
- **禁止**在运行代码里写"每天最多 N 条""至少静默 M 分钟"这类配额；这些数字只允许出现在测试断言与审计脚本里。
- 取消测试：把"经过时间"这条老路径加回去（或删掉事件触发）⇒ 回放用例红（静默上限塌回 <10 分钟、无法追溯原因）。

## 顺序与依赖

```
P1a（止血） → P2（世界记忆） → P3（意图+动手） → P1b（有动机的谎放行） → P4（节奏 2.0）
```

- P1a 先做：她正在编，先止住；P1a 的"动机源"要等 P3，故 P1b 放在 P3 之后。
- P2 是 P3 的前提（读到的要能落库）。
- P4 最后：它需要 P3 提供"事件源"，否则"有事才说"没有事可说。
- 每片单独 commit + `scripts\gate.ps1`（基线 **800 passed + 13 skipped**）+ 取消测试。
