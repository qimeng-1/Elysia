## 零、通用规则（每条都适用，**先读这段**）

### 首帧

- 用 `D:\图片\elysia_firstframes\` 里的图（→ 已抠干净、**纯白底**、无 logo）
- ⚠️ **绝不要直接喂游戏截图或带 logo/文字的图**
  > 实测教训：`雀跃.mp4` 左上角整个**「崩坏3」logo 被 AI 一起动起来了**
  > （12,555 像素的独立块，比噪点大得多）。喂进去什么，AI 就会动什么。

### 输出要求

| 项 | 要求 | 为什么 |
|---|---|---|
| 背景 | **纯白** `#FFFFFF` | 抠图最容易。实测：喂白底 → 输出就是 252,252,252 |
| 镜头 | **完全固定**（不推拉/旋转/缩放） | 桌宠素材必须固定机位，否则没法用 |
| 角色 | 外观/服装/配色/发型/画风**严格不变** | 变脸换装就不能用了 |
| 文字 | **不要任何文字、水印、logo、字幕** | 深色角标抠图去不掉 |
| 时长 | **4–6 秒** | 循环段要够长才不单调 |
| 分辨率 | **≥720P** | 缩到桌宠尺寸（约 400px 高）仍要清晰 |
| **动作幅度** | **必须明确写出来**（"明显""大幅度""清晰地"） | ⚠️ 实测写"极轻微"→ 输出几乎静止，**白费一次生成**（MiniMax 那次就是这样） |

### 循环段 vs 单次段

- **循环段**（待机/睡眠/疲惫/思念/张望）：**首尾姿态要一致**。我会用工具量（剪影差 < 3、整图差 < 8 才算无缝）
- **单次段**（点击回应/打招呼/落地）：不需要首尾一致，但要**从站定开始、回到站定结束**——这样接回待机不跳

### 命名

生成后请按 `<动作ID>.mp4` 命名（下表每条都有 ID），例如 `settle.mp4`、`wave.mp4`。

## 模板与参数（Seedance 2.0 Mini / 豆包）

**结论：模板可用，但「动作」之外有 4 处必须改、4 处建议改。**

### ✅ 不用改

| 参数 | 为什么 |
|---|---|
| 模型（Seedance 2.0 Mini） | 已验证可用：7 条素材全部成功抠图入库，角色保持度好 |
| 镜头完全固定 | 桌宠素材必须固定机位，否则没法用 |
| 背景纯白 `#FFFFFF` | 实测输出 246–252，抠图几乎零毛边 |
| 一致性（外观/配色/服装/画风/头身比） | 实测角色保持得很好（MiniMax 那次也是） |
| 不加文字 / 水印 / 转场 | 深色角标抠图去不掉，必须从源头杜绝 |

### ⚠️ 必须改的 4 处（每条都有实测证据）

| # | 原写法 | 改成 | 证据 |
|---|---|---|---|
| 1 | 「**无大幅肢体位移**」 | 「**身体位置与大小固定在同一处，但肢体动作要做足、清晰可见**」 | 这句很可能是 `注意到我` **动作偏小**的元凶：实测运动均值仅 0.95、96 帧里只有 33 帧有效运动。模型把"无大幅位移"理解成"别动"了 |
| 2 | （没写） | 加「**角色在画面中的大小始终不变**」 | `被拎起悬空` 是**被 AI 画大了 25%**（源内高 695px vs 待机 554px），直接破坏了跨片段的尺寸一致性，逼我做了统一画布归一化 |
| 3 | （没写） | 加「**不要地面投影/阴影/渐变**」 | 投影会连在脚下，被当成角色的一部分抠进去，在深色桌面上就是一团脏影 |
| 4 | （没写） | 加「**不要肢体融化、多余手指**」 | AI 视频的常见伪影，抠图后特别明显 |

### 💡 建议改的 4 处

| # | 项 | 建议 | 理由 |
|---|---|---|---|
| 5 | **时长** | **统一都填 5 秒，不用区分** | 实测：要 5 秒实际得到 **97 帧 ≈ 4.04 秒**（5 条素材全是这个数）。单次动作末尾的空转我自己裁，**你不用管时长** |
| 6 | 「首尾姿态一致」 | **只对循环类这么要求**；单次类改成「**从站定姿态开始、以站定姿态结束**」 | "首尾一致"对单次动作是错的，而且可能让模型**为了回到起点而抑制动作幅度** |
| 7 | **帧率** | **30fps 优于 24fps**（别要 60） | 素材帧率越高 = 动作信息越多 = 越顺。但 AI 通常在 ~24fps 内部生成、再重复帧凑到 60，反而可能有伪影 |
| 8 | **画质/分辨率** | **尽量选最高（1080p 优先）** | 最终要抠图 + 放到桌宠尺寸，源越大越清晰。目前 720p 下她只有约 550–700px 高 |

### 📌 待机 / 循环类额外必加一句

```
全程保持眼睛睁开，眨眼不超过 0.2 秒，不要闭眼或打盹。
```
> 踩坑记录：`睁眼呼吸.mp4` 全程 241 帧里只有 f0–f16、f212–f240 是睁眼的，
> **f20–f204（6.7 秒）她闭着眼**——直接循环等于一直在睡。我最后是裁到 f212–f240 才救回来。

### 🎬 每次只需要换「动作」部分

| 类别 | 动作 ID | 时长怎么填 | 首尾要求 |
|---|---|---|---|
| **循环** | `idle-open` `sleep` `tired` `miss` `think` `sad` `look-around` | **5 秒** | **首尾姿态必须一致**（我会验剪影差 < 3、整图差 < 8） |
| **单次** | `notice` `settle` `wave` `shy` `surprise` `pout` `land` | **5 秒** | **从站定开始、回站定结束**（末尾空转我裁） |
| **拖拽状态** | `grab` | **5 秒** | 循环类；我会用**乒乓**播放兜底接缝 |

> 实测参考（已入库 7 条的源规格）：全部 **720×720（1:1）**、24fps（`grab` 是 30fps）、
> 每条约 **97 帧 ≈ 4.04 秒**。所以"比例 1:1 + 5 秒"这个组合是**验证过的**，保持即可。

## 零之二、**反应类动作必须短**（`notice` 的教训）

`notice`（注意到你）原本 97 帧 4.04 秒，实测动作轮廓是：

```
f0 → f46   持续抬头（1.9 秒）
f46 → f96  保持"抬头看着你"的姿势不动，直到结束（**2.1 秒纯空转**）
```

鼠标在桌面上移动会**反复进出窗口**，于是这条 4 秒的动画被不停重播，
把待机轮换和整体节奏全打乱了（用户实测反馈："注意到我这一个动作导致了整体的不流畅"）。
修法两条，都做完了：

1. **裁短**：只取抬头完成的那一段（f0–f42）并以 30fps 播放 ⇒ **1.40 秒**
   （命令：`--frames 0:42 --fps 30`）
2. **加冷却 25 秒**：冷却期内鼠标再进出窗口**不再重播**

> **生成时的要求**：反应类动作（`notice`/`shy`/`surprise`/`pout`）请把动作**做得紧凑**，
> 抬头/惊讶/害羞这类"瞬间反应"应该 **1–1.5 秒内完成**，不要出现"摆好姿势后长时间不动"的尾巴。
> 提示词里可以写：「动作在前 1.5 秒内完成，之后不要保持姿势不动，自然回到站姿」。

### ⚠️ 两条实测教训（2026-10-15 新增）

**1. 落地类动作请只做"一次"落地，不要做成弹跳循环。**
`高处落地或弹跳.mp4` 实测 10 秒里有 **3 次落地弹跳**（运动峰值在 f12 / f84 / f180），
是"弹跳循环"而不是"一次落地"。我最后只能截取其中一次（f60–f108 = 2.0 秒）当 `land`。
⇒ 提示词请写：「**只落地一次**，落地后自然站定并保持，不要反复弹跳」。

**2. 待机类动作 2–5 秒就够，别做 10 秒。**
`东张西望.mp4` 是 241 帧 10 秒——虽然无缝循环、质量很好，
但长片段会明显增加内存与重复感（见下）。
⇒ 待机/张望类 **3–5 秒**最合适。

### 🧠 内存（`look-around` 让我发现的一个真问题）

序列帧播放器原先**一次性把整段解码成 QPixmap**：460×620 RGBA 每帧 1.14 MB，
实测九段合计 **937.8 MB**（进程内存涨到 356 MB 时我才发现）。
现已改为**按需解码 + 16 帧滑动窗口**，九段合计降到 **154.5 MB（-84%）**，
而且**加载片段变成瞬时**（切换不再有解码卡顿）。
⇒ 不过素材还是别做太长：长片段的**磁盘与加载**成本仍然随帧数线性增长。

## 一、第一批：**过渡动作**（最急，专治"切换不自然"）

> **为什么最急**：现在的切换是**硬切**——待机最后一帧直接跳到回应第一帧，看着"啪"地一跳。
> 有了这几个"预备/收尾"动作，再加我做的**交叉淡入淡出**，过渡就会像 dsh-pet 那样顺。
> 这一批**只有 5 条**，但对观感的提升最大。

### 1. `notice` 注意到你 ｜ 单次 2 秒

**用途**：她要做任何动作**之前**的预备动作（抬头、眼神收过来）。用它替掉硬切。

```
她原本安静站着，随后明显地抬起头、把视线转到正前方看向镜头，头部动作清晰可见，
肩膀随之微微一抬，动作幅度明显但优雅；结束时停在抬头看镜头、面带微笑的姿势。
```

### 2. `settle` 归位站定 ｜ 单次 2 秒

**用途**：动作**结束后**回到待机。**这条是"过渡自然"的另一半**。

```
她轻轻吐出一口气，肩膀放松地落下，身体左右轻微晃动两下后逐渐站定，
头发与裙摆因惯性轻微摆动后慢慢平静；结束时回到安静站立的姿势。
```

### 3. `float` 漂浮起来 ｜ 循环 5 秒 ⭐ **用户要求：替换掉原来的"被拎起悬空"**

**用途**：**按住拖拽期间**播放（对应 dsh-pet 的 `drag` 池）。
**关键区别**：不是"被一只手拎着"，而是**失重漂浮**——她应该像浮在空中/水里，而不是被抓住。

```
她处于失重漂浮状态：双臂与双腿自然放松地向下舒展，头发与裙摆缓慢地向上飘起并轻轻摆动，
身体以很缓慢的节奏上下浮沉、并伴随极轻微的旋转；表情平静放松、带一点好奇，
不要出现被抓住、挣扎、紧绷或下坠的姿态；整个动作循环流畅。
```

> 素材到位前，我已经在**表现层**先做了漂浮手感（被按住时轻轻上下浮沉 7px / 0.55Hz
> ＋ 轻微摆动 2.2°），所以现在拖她**已经不是"拎着"的观感**了。
> 生成后放进 `assets/pet/costumes/c1/float/`，程序会**自动优先用它**（候选顺序 `float` → `grab`）。

### 3b. 旧的 `grab` 被拎起悬空（已被 `float` 取代，保留备查）

```
她像被一只无形的手从上方拎起来一样：双臂自然下垂并略微向上收拢，双腿悬空并轻轻摇晃，
身体因悬空而缓慢左右摆动、头发向下垂坠飘动，表情略显惊讶但很放松；整个动作循环流畅。
```

### 4. `land` 落地缓冲 ｜ 单次 1.5 秒

**用途**：松手落地后蹲一下再站直，配合物理弹跳（对应 dsh-pet 的落地压缩）。

```
她从高处落下接触地面：落地瞬间双腿明显弯曲、身体向下压缩变矮，
然后有弹性地伸长恢复、站直，头发和裙摆因下落惯性向上扬起后落回；结束时回到站立姿势。
```

### 5. `look-around` 东张西望 ｜ 循环 5 秒

**用途**：她的"张望/漫游"状态（对应 dsh-pet 的 `turn` 池）。

```
她左右转头张望：先向右转约 30 度停留一下，再向左转约 30 度停留一下，
身体跟着视线微微转动，头发有小幅摆动，表情好奇；动作连贯循环。
```

## 二、第二批：待机与点击回应

### 6. `idle-open` 睁眼待机呼吸 ｜ 循环 5 秒 ⭐ **最要紧**

**用途**：主待机。**现在唯一的待机是闭眼的**（豆包那条 `呼吸.mp4` 全程闭眼），看着像一直在睡。

```

身体重心有极细微的左右移动；**全程保持眼睛睁开**，只在中间快速眨一次眼（不超过 0.2 秒），
不要闭眼、不要打盹、不要低头合眼；动作柔和平缓，循环自然。
```

> 开头 17 帧与结尾 29 帧是睁的）。所以现在改成"全程睁开 + 一次快速眨眼"的强约束。

### 7. `cheer` 开心雀跃 ｜ ✅ **已有**（`雀跃.mp4`）不用重做

她开心地抬起右手，明显地挥手打招呼两到三次，手掌左右摆动幅度清晰，

她先是微微一愣，随后脸颊泛红、明显地低下头，双手抬起来轻轻捂住脸，

### 11. `pout` 鼓起腮帮 ｜ 单次 2.5 秒

她把脸转向一侧并明显地鼓起腮帮子，双手抱在胸前，眉毛微微皱起，

## 三、第三批：**灵魂状态驱动**（这些才让她是"她"，而不是挂件）

> 这一批是**接她的真实状态**用的：`tired` 接低 TR / 显存高压、`miss` 接高思念、
> `sleep` 接深夜与离线、`think` 接好奇与自检、`sad` 接低 SA。

### 12. `sleep` 睡眠 ｜ 循环 6 秒

```
她闭着眼睛睡着了：身体随着缓慢而深长的呼吸明显起伏，头轻轻一点一点地向下垂，
偶尔身体向一侧歪一下又慢慢稳回来，头发随之轻微晃动；动作极其缓慢平稳，循环自然。
```

### 13. `tired` 疲惫 ｜ 循环 4 秒

```
她看起来很累：肩膀明显地垮下来，头低垂着，胸口起伏变快变浅，
一只手抬起来揉了揉眼睛，身体疲惫地前后轻晃；动作缓慢沉重，循环自然。
```

### 14. `miss` 思念远望 ｜ 循环 5 秒

```
她安静地望向远方：头缓缓转向一侧并微微抬起看向远处，眼神有些出神，
随后轻轻叹一口气、肩膀落下，头发被轻轻吹动；动作缓慢，循环自然。
```

### 15. `think` 思考发呆 ｜ 循环 5 秒

```
她陷入思考：一只手托住下巴，眼睛看向斜上方，头轻轻歪着并缓慢地小幅左右摆动，
另一只手无意识地轻轻点着，头顶偶尔飘起一两个小小的思考气泡；循环自然。
```

### 16. `sad` 难过 ｜ 循环 4 秒

```
她情绪低落：低着头肩膀微微内收，眼睛半垂着，嘴角向下，
胸口有轻微的抽气起伏，身体几乎不动，只有头发和裙摆极轻微地摆；动作安静缓慢，循环自然。
```

## 四、与 dsh-pet 槽位的对应关系（将来若做 pet pack 可直接映射）

| dsh-pet 配置槽位 | 我们的动作 ID | 状态 |
|---|---|---|
| `animations.idle`（数组，等概率抽） | `idle-open` / `look-around` / `think` / `sleep` | ⏳ 待生成 |
| `animations.turn`（播完需翻转朝向） | `look-around` | ⏳ |
| `animations.drag`（被拎起姿势） | `grab` | ⏳ |
| `animations.clicks`（点按随机抽 1） | `cheer` ✅ / `wave` / `shy` / `surprise` / `pout` | 1/5 |
| `animations.moves`（行进；需最小/最大距离） | **缺**：需要一段 `walk` 走动 | ❌ |
| `events`（余额/工作状态驱动） | 不适用（我们接灵魂状态，不接 DSH 状态） | — |

> 注：dsh-pet 的"转向"要求动画**播完会翻转朝向**。我们单方向桌宠不需要真翻转，
> `look-around` 用来满足"张望/漫游"的表现即可。

## 五、优先级与批量建议

| 批次 | 内容 | 条数 | 效果 |
|---|---|---|---|
| **先做这批** | `notice` `settle` `grab` `land` + `idle-open` | **5** | 过渡自然度直接上一个档次 + 告别"一直在睡" |
| 第二批 | `wave` `shy` `surprise` `pout` `look-around` | 5 | 点击回应变丰富（现在只有 1 种） |
| 第三批 | `sleep` `tired` `miss` `think` `sad` | 5 | 她的**真实状态**看得见了 |

**建议：先只做「先做这批」的 5 条。** 生成完我立刻入库，你先在桌面上看观感对不对，
确认方向之后再做第二批——**别一次生成 15 条**（方向不对就全白费）。

## 六、生成后我这边会自动做的事

1. **抠图**：从纯白底抠出透明序列帧（纯白底容差小，基本不会有毛边）
2. **查循环性**：剪影差 < 3 且整图差 < 8 才算无缝；不达标的我会告你，你重生成或接受
3. **编码**：VP9-alpha `.webm`（dsh-pet 兼容）+ WebP 序列（我们桌宠的运行时格式）
4. **入库**：放进 `assets/pet/costumes/<服装>/<动作ID>/`，你右键菜单里立刻多出这个动作
5. **验证**：我出对比图给你看，确认没问题再进下一步
