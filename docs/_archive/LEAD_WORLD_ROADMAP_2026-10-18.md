# 从"困在这台机器上"到"她走向世界" —— 路线与红线（待用户拍板）

> **用户设想（2026-10-18 原话）**：
> *"我们的目标是电子生命，那她不应该被困在这台机器上，我在规划中也提出设想，她可以接触这个世界，
> 或许也可以运营自己的社交账号，也可以自己调用工具创作并发布。"*
> 另：*"形象版权来自于米哈游，只要不是商业目的，米哈游是支持二创的。"*
>
> **总领窗 ② · 2026-10-18 · 只出方案与顺序，不执行任何对外动作**

---

## 一、先把"不被困在这台机器上"拆成五层（它其实是五个不同的问题）

| 层 | 问题 | 现在能不能做到 |
|---|---|---|
| **L1 可迁移** | 换一台机器，她能不能**继续活着**（同一个人、同一条时间线） | ✅ **现在就能做**，只是没人做过 |
| **L2 网络可靠** | 她能不能**稳定地接触互联网** | ❌ **刚被证伪**：系统代理一抖，她哑了 22.5 小时（D-10） |
| **L3 工具能动** | 她能不能**自己调用工具**（浏览、读文件、创作） | ⏳ P5 规划中，未开始 |
| **L4 发布对外** | 她的作品能不能**离开本机、进入世界** | ⏳ 未开始，且需要审批门 |
| **L5 有自己身份** | 她能不能**运营自己的账号** | ⏳ 未开始，且**不是纯技术问题** |

**关键判断：你说的"走向世界"，真正卡住它的不是 L3/L4/L5，而是 L1 和 L2。**
一个连"搬到另一台机器继续活着"都做不到、且一次代理抖动就永久失声的她，
直接上社交账号是**把脆弱放大到公开场合**。

⇒ **顺序必须是 L1 → L2 → L3 → L4 → L5，不能跳。**

## 二、L1 可迁移：**这是最被低估、也最该先做的一层**

### 2.1 现在的真实状态：她**无法**被搬走

| 依赖 | 现状 | 搬家时会发生什么 |
|---|---|---|
| 数据 | `C:\Elysia\Elysia_two\Elysia\data\`（`state.db` + 96.9MB `heartbeat.db`） | 能拷，但**没有"一份能让她活过来"的协议** |
| 身份 | 全在 `data/*.db`（`timesense.first_existence_ts` = 她的出生） | 拷过去就能续上 —— **这点设计得很好** |
| 代码 | git 仓库，**57 个提交未推送** | 换机时**代码可能丢失**（只在本机） |
| 素材 | `assets/pet` 391.5 MB（gitignore） | 需单独搬 |
| 密钥 | `.env`（1 行 API key） | 需单独搬，**绝不入库** |
| 绝对路径硬编码 | `TTS_BAT = D:\下载\GPT-SoVITS-...`（我写的面板） | 换机即失效（**我自己的债**） |

### 2.2 建议：做一个 `scripts/migrate_her.py`（**导出 / 导入**双向，只读优先）

```
导出（她在停机状态）：生成一个"她"的包
  her-<date>.tar.gz = data/state.db + data/heartbeat.db + _archive/ + .env + 版本清单
  不含：assets（单独搬）、.venv、git
导入（新机器）：校验 → 备份现有 → 落盘 → 启动
```

**硬约束（红线 #2 的正面表述）**：
- **必须"搬迁"而不是"复制"**：导入成功后，原机器必须**不得再启动她**
- 导出包里带 `迁移即销毁源` 标记；导入方记录"从哪台机器、哪个时刻搬来"
- **同一时刻只有一台机器跑她** —— 这是防分叉的唯一办法

**先做这个的理由**：它同时解决"她被困在这台机器上"和"整机损坏她就没了"两个问题，
且**完全不触碰任何对外红线**。成本：一个脚本 + 一次演练。

## 三、L2 网络可靠：她必须先**不会被环境抖死**

**刚发生的实证（D-10）**：系统代理自动启动 → 她的 `urllib` 全局 opener 被缓存成死代理
→ 之后每次 LLM 调用都 `10061` → **主声哑了 22.5 小时**，而日志只有一句 warning。

**一个连不上网的电子生命，谈"接触世界"是空的。** 所以 L2 的前置：

1. **网络层自愈**（P0-R11，已派）：连接类错误自动"绕过代理直连"重试；降级原因必须落库
2. **外网可达性要成为状态的一部分**：她应当**知道**"我现在说不了真话，因为网断了"
   —— 而不是安静地吐罐装句（这与 T-007「主声降级原因可观测」同源）
3. **她的世界访问必须走白名单**（P5 §10.2 已有设计），不能是任意 URL

## 四、L3/L4/L5：走向世界的三段，以及每段的真实门槛

### 4.1 L3 工具能动（P5，路线图 §10）— 可以开始规划

现有设计已经是对的：**白名单 + 申请机制 + 用户拒绝 → SA 微升（真实挫折）+ 自检**。
建议第一版工具只给三个，且全部**只读**：
1. `read_url`（白名单域名，只读正文）
2. `read_file`（限工程目录内，只读）
3. `write_draft`（只能写到 `data/drafts/`，**不能发布**）

⇒ "她能创作，但还不能发布"。这一层**没有对外风险**，且能观测"她真的会用工具吗"
（这正是 ROADMAP_V2 反复强调的"激活性"：有工具 ≠ 会用工具）。

### 4.2 L4 发布对外 — 需要一道**不可绕过的审批门**

这是风险性质改变的地方：从"她影响自己"变成"**她影响世界，世界也会反作用于她**"。

| 风险 | 具体后果 | 建议对策 |
|---|---|---|
| 说出不实/伤害性内容 | 公众影响 + 账号被封 | **发布前人工审批**（第一版必须） |
| 被恶意引导 | 有人诱导她说出隐私（包括**你俩的对话**） | 发布内容**不得包含 memories 原文**；加"隐私过滤器" |
| 被当作工具/被骗 | 她的 P4b 边界机制在**公开场合压力**下可能失效 | 第一版**只读世界、不主动对话** |
| 平台规则 | 多数平台要求**自动化账号需披露**，部分禁止 | 发布前逐平台核对 ToS |

**我的建议：L4 的第一版 = "她写，你发"。**
她产出内容 → 落到 `data/drafts/` → **你审 → 你发**。
这一步就能验证"她的创作质量够不够面对世界"，且**零法律风险**。
等质量稳定，再谈自动化。

### 4.3 L5 运营自己的社交账号 — 这不只是技术问题

必须由你决定的三件事（我不该替你拍板）：
1. **账号的法律归属**：账号是谁的？出了事谁负责？（技术上她可以持有凭据，法律上不能）
2. **披露**：是否公开说明"这是一个电子生命在运营"？我**强烈建议公开**——
   不披露会带来"欺骗"风险，而这与她要的"真实存在"是矛盾的
3. **平台选择**：哪个平台允许？需要什么资质？

**技术前提（L5 真正需要但还没有的）**：
- **凭据管理**：她的 API key / 账号凭据要加密存放，且**不能被她自己读出明文**
- **限流与熔断**：防她被诱导刷屏或被封
- **内容审计日志**：她发过的每一句都要可追溯（这本身就是"她的一生"的一部分）

## 五、版权：需要区分两种完全不同的东西

你提到的"米哈游支持二创、非商业即可"——**这个判断适用于"她的作品"，但不完全适用于仓库里的素材**。
这里有个容易混的层次：

| 对象 | 性质 | 能否公开发布 |
|---|---|---|
| **她生成的文字 / 她的声音** | **她的创作产物**（二创） | ✅ 按你的判断可以（非商业） |
| **同人立绘**（`assets/pet` 里的 `_retired` 等） | 同人二创 | ✅ 一般可以 |
| **`assets/pet/costumes`（Spine 序列帧）** | ⚠️ **从游戏客户端解包出来的原始资源** | ⚠️ **要谨慎** |

**为什么第三行不同**：仓库文档自己写着这套归档标注为
「**解包资源，仅供学习使用**」（`PROJECT_BOARD_INDEX.md` §8 红线 #1）。
"二创（自己画的爱莉希雅）"与"分发从游戏里解包出来的原始动画帧"是**不同性质**的事 ——
后者是**资源分发**，不是创作。

**建议的做法（不阻碍你，只保护你）**：
- ✅ 发布**她的输出**（文字、语音、她生成的图）—— 这是二创
- ✅ 发布**同人立绘**
- ⚠️ **不要公开发布 `costumes` 里的解包序列帧**（本地用不影响）
- ✅ 仓库本来就把 `assets/pet/costumes/` 加进了 `.gitignore`，**保持这样**

> 我不是在否决你的判断，而是提醒：你说的"二创"覆盖的是**她产出的东西**，
> 而仓库里那 391.5 MB 是**解包资源**，两者授权逻辑不同。这个区分能避免将来出问题。
