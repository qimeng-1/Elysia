# Elysia 迁移与完整性手册

> 回答一个问题：**换设备 / 恢复环境时，怎么保证一个文件都不丢、配置全部还原。**
> 配套工具：[verify_integrity.py](../工具脚本/scripts/verify_integrity.py) · 配套清单：[file_manifest.json](../项目元信息/file_manifest.json)

---

## 一、核心原则

1. **GitHub 仓库 = 权威副本**：文档、脚本、代码、配置存档全部进 git，换设备 = clone 一次
2. **大文件独立备份**：声音模型权重/runtime（数 GB）不进 git，走网盘/移动硬盘
3. **完整性靠工具不靠记忆**：迁移后跑校验脚本，缺了什么机器告诉你
4. **路径只写相对**：全项目禁止绝对路径，换设备无需改路径（见第四节）

---

## 二、仓库边界（什么进 git，什么不进）

| 进 git（clone 即得） | 不进 git（独立备份） |
|---------------------|---------------------|
| 全部 .md 文档（设计规划/工程标准/灵感管理/项目元信息/配置存档） | `声音模型/` 整个目录（权重、runtime、音频素材） |
| 工具脚本 `工具脚本/scripts/` | `runtime/`、`__pycache__/` 等环境残留 |
| 配置存档 `配置存档/声音模型/`（3 个改过的配置副本） | 密钥/`.env`（绝不进仓库） |
| 未来代码库与 `data/` 记忆快照 | `data/cache/` 等临时数据 |

> 边界由根目录 [.gitignore](../.gitignore) 强制执行。修改边界时同步更新本表。

---

## 三、换设备完整流程

### 新设备准备（一次性）

1. 安装 Python 3.12+、git
2. **clone 仓库**（文档 + 脚本 + 配置存档 + 未来代码）
3. **从备份恢复大文件**：将 `声音模型/` 整个目录拷回项目根（网盘/移动硬盘/旧设备直拷）
4. **恢复声音配置**：把 `配置存档/声音模型/` 的 3 个文件复制回 `声音模型/GPT-SoVITS-v2pro-20250604/` 对应位置（详见存档 README）

### 完整性验证（每次迁移必做）

```bash
# 第 1 步：验证全项目文件完整（缺失/变更一目了然）
python 工具脚本\scripts\verify_integrity.py --check

# 第 2 步：验证声音模型大文件（备份端生成清单，恢复端比对）
#   备份时：在 声音模型/ 目录运行
python -c "import hashlib,os;[print(f'{hashlib.sha256(open(os.path.join(r,f),\"rb\").read()).hexdigest()}  {f}') for r,_,fs in os.walk('.') for f in fs if os.path.getsize(os.path.join(r,f))>1e7]"
#   恢复后：同样的命令，比对输出是否一致（或使用任意文件校验工具）

# 第 3 步：确认工具可用
python 工具脚本\scripts\verify_integrity.py --check   # 应输出 [PASS]
```

### 验收确认（迁移完成标准）

- [ ] `--check` 输出 `[PASS]`（无缺失、无变更）
- [ ] `声音模型/` 校验和与备份端一致
- [ ] `启动ElysiaAPI.bat` 双击可启动（API 在 127.0.0.1:9880）
- [ ] 全部文档链接可打开（从 项目元信息/PROJECT_MANIFEST.md 逐个点）

## 四、路径规范（防"牵一发而动全身"）

> 迁移麻烦的根源是路径硬编码。以下规则从今天起生效：

1. **禁止绝对路径**：项目内任何文件（文档/脚本/代码）不得出现 `盘符:\...` 形式路径
2. **目录结构冻结**：顶层 7 个分类目录（设计规划/工程标准/灵感管理/工具脚本/声音模型/配置存档/项目元信息）不改名、不移动、不增减；新文件只进已有分类
3. **脚本路径推导**：脚本用 `%~dp0`（bat）或 `__file__`（Python）推导项目根，禁止写死跳层数以外的路径
4. **文档链接单一入口**：跨目录链接只允许出现在 `项目元信息/PROJECT_MANIFEST.md`；文档间引用用文字描述 + 索引链接
5. **代码路径集中管理**：未来代码库中所有路径基于项目根推导，集中在一个配置模块

## 五、定期维护

| 时机 | 动作 |
|------|------|
| 项目文件有增删改后 | 运行 `verify_integrity.py --generate` 更新清单，并提交 git |
| 上传 git 前 | 确认 `.gitignore` 边界正确（`git status` 无大文件混入） |
| 上传 git 后 | 从新位置 clone 一次，跑 `--check` 验证仓库自包含 |
| 声音模型有变更 | 同步更新 `配置存档/声音模型/` 的副本 |

## 六、常见问题

**Q：不小心在文档里写了绝对路径怎么办？**
换设备时 `--check` 抓不到（它校验文件内容一致性，不校验路径语义）。迁移时如果发现链接失效，搜索 `盘符:` 全局排查。建议严格遵守第四节规则 1。

**Q：声音模型备份丢了，只剩 git 仓库？**
模型权重无法从 git 恢复（本来就不在仓库）。所以备份要双份：网盘 + 移动硬盘。这也是大文件不进 git 的原因——git 不是备份工具，是版本工具。

**Q：为什么 data/ 要进 git？**
她的记忆、状态是生命数据。进 git = 每次提交都是记忆快照，可回溯可恢复。但注意：敏感内容加密后提交，密钥不进仓库。
