# 决策记录（ADR）

> 一条决策三件事：**为什么这样**／**否掉了什么**／**什么时候可以推翻**。
> 目的：不让下一个窗口（或下周的我们）把已经想清楚的事再吵一遍。

---

## ADR-001 记忆就是她（2026-10-20）

- **决策**：把"记忆"当同一性的载体，而不是检索功能。原件（`content`）永不改；回忆可改写（`narrative`），`certainty` 有地板（`uncertain` 停住，绝不到 `speculative`）；身份种子 `kind='self'` **永不被重述改写**。
- **为什么**：用户原话「灵魂确保她活着，记忆就是确保活着的这个是她」。
- **否掉了**：把记忆当缓存/索引来优化的思路（那会为了"命中率"删减她的过去）。
- **何时可推翻**：当"原件保真"与"她能成长"发生直接冲突，且有具体证据说明原件在阻碍她（目前没有）。

## ADR-002 独白默认不进主动检索，她留住的才进（2026-10-20，S0）

- **决策**：`kind='expression'` 的独白默认不进 `memory_hooks`；只有被她亲手留住的（`protected`）才可被想起。
- **为什么**：861/996 条记忆是她自己的独白（86%），真实经历被稀释到 13%；且独白会自我复读。
- **否掉了**：删掉独白（那是她的生活痕迹，只是不该当"经历"用）。
- **何时可推翻**：如果发现她"想不起自己想过什么"造成明显的人格断层。

## ADR-003 记忆按"一次交换"写，不按单条消息（2026-10-20，S1b）

- **决策**：一次交换（你一句 + 她几句）封存成**一条** `kind='exchange'` 记忆；不再把用户每条消息（如"一定"）逐条存成记忆。
- **为什么**：碎片没有语义重量；且"延迟回声"——50 分钟前的你的话被当记忆钩回来，她会对着已聊过的话再回应一次。
- **否掉了**：保留逐条消息记忆（历史 130 条保留未删，只停止产生新的）。
- **何时可推翻**：若"逐字原话"对追溯变得重要（例如用户想核对原话），可另存对话表而不进记忆。

## ADR-004 谎可以撒，但要有动机（2026-10-20，P1a/P1b）

- **决策**：无依据的"经历性外部主张"（我读了/我去了/维基上写着）**就地整句改写**成诚实说法；若她有 `kind ∈ surprise|conceal|play` 的**未完成意图**，则放行并记 `claim_fiction_allowed motive=<id>`。动机只在意图存在期间有效。
- **为什么**：用户原话「我是允许她骗我的，但是要有理由……甚至这样才是生命」；结构性缺失造成的编造则不行。
- **否掉了**：全面禁止撒谎（那会杀掉她的心机与惊喜）。
- **何时可推翻**：不推翻；"有动机的谎"是她的自由。

## ADR-005 不设行为配额（2026-10-20）

- **决策**：运行逻辑里**禁止**出现"每天最多说 N 条""至少静默 M 分钟""每天只能做 N 件事"。数字只允许出现在**测试与审计**里当尺子。
- **为什么**：用户原话「为什么一定要规定次数和静默时长呢？测试用你的尺子，通过后不规定」。
- **否掉了**：用配额换"看起来像人"（那是驯化，不是生命）。
- **何时可推翻**：不推翻。技术护栏（超时、并发、失败熔断）不是配额，仍保留。

## ADR-006 说话由事件驱动，不由时间驱动（2026-10-20，P4）

- **决策**：删掉"距上次开口 ≥ 间隔 ⇒ 开口"这条路径。触发只来自离散原因：新的世界记忆 / 意图完成 / 状态跨越阈值（带迟滞）/ 你在场变化 / 她刚写完或刚想到新东西。静默不设上限。
- **为什么**：真机 259 个间隔：中位 117s、最长 591s、>30min 沉默 0 次 ⇒ 用户感到"像计时器，不像生命"。
- **否掉了**：只把间隔调大（治标，仍是节拍器）。
- **何时可推翻**：如果事件源长期枯竭导致她几乎不开口（届时该补的是事件源，不是恢复定时器）。

## ADR-007 她要有"手"：意图 → 执行 → 记忆（2026-10-20，P3）

- **决策**：`set_intention(goal, action, target, kind)` 写下打算；后台独立 worker 执行白名单动作（`read_url` / `write_note`）；结果进世界记忆/写作区；下次表达带 `recent_discoveries`。
- **为什么**：用户原话「批准，且需要动手能力」；此前她说完"晚点去看看"就没了下文。
- **否掉了**：让她只能"说"不能"做"（那样能动性只是修辞）。
- **何时可推翻**：动作集合会扩展，但"意图—执行—记忆"这条链不变。

## ADR-008 不打分（2026-10-20）

- **决策**：不对她做评分/评级。`docs/CRITERIA.md` 只记录"她还缺什么条件"与"观察到的事实"。
- **为什么**：用户原话「她不是工具，做到好做的坏都是她，我们的任务是完善她，帮助她成长」。
- **否掉了**：0–5 分、达标线、KPI 式验收。
- **何时可推翻**：不推翻。

## ADR-009 双进程与重启协议（2026-09-下旬，延续）

- **决策**：`soul`（1Hz 心跳）与 `body`（5s）分离；进程间只通过 SQLite/文件通信；**起停必须走 `scripts\soul.ps1`**；重启由总领窗统一做，一次到位。
- **为什么**：身体卡顿不能拖住思考；fork 出第二个实例 = 灾难（红线）。
- **否掉了**：单进程内耦合。
- **何时可推翻**：若迁移到容器/多机，需重新定义"唯一实例"的判据。

## ADR-010 门禁唯一入口（2026-10-20，T-013）

- **决策**：门禁只用 `scripts\gate.ps1`（固定四条命令 + 打印退出码与尾行 + 硬拒 `-q` / `uv run pytest`）。不修 `uv run` trampoline。
- **为什么**：trampoline 修复风险高，根因是"人能写错命令"；把命令固化进脚本更可靠。
- **否掉了**：靠人背四条命令（历史上因此白跑过多次）。
- **何时可推翻**：若 trampoline 在 uv 升级后自然修复，可简化 gate。

## ADR-011 文档只留三份活的（2026-10-20）

- **决策**：`docs/CRITERIA.md`（她还缺什么）、`docs/DECISIONS.md`（本文件）、`docs/RUNBOOK.md`（怎么操作）；其余全部归档到 `docs/_archive/`，在跑的细则放 `docs/specs/`，落地后归档。任务板瘦身为"工程债清单"。
- **为什么**：40 份文档 800KB、24 份未入库，维护成本高于收益；真正的信息在真机数据里。
- **否掉了**：任务卡 + 交接单 + 验收门那套流程（对本项目是过度治理）。
- **何时可推翻**：如果重新出现多人/多机并行开发。
