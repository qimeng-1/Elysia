## ⚠️ 执行中真实发生的两次失败（必须留档，别美化成"一次成功"）

本窗口第一次执行（23:35:40）**中止了，没换库**，原因是我自己的工具缺陷：

| # | 缺陷 | 现象 | 修法 |
|---|---|---|---|
| 1 | **验收器打印 emoji** | 32 项**其实全部 PASS**，但脚本结尾要打印 `✅`，而 Windows 控制台是 **GBK** ⇒ `UnicodeEncodeError` ⇒ 脚本**以非零码退出** ⇒ `execute_memory_merge.ps1` 判定"验收未通过"、**拒绝换库**并把她重新拉起 | 结论行改为纯 ASCII（`ALL PASS` / `N FAILED`）；并在执行脚本里固定 `PYTHONIOENCODING=utf-8` |
| 2 | **`.ps1` 每次都丢 BOM** | 编辑器写文件不带 BOM，而 Windows PowerShell 5.1 按 **ANSI** 读中文 ⇒ 语法撑破、脚本根本不能运行。**本窗口为此连踩 3 次** | 每次改完 `.ps1` 必须补 UTF-8 BOM，并**解析器复核**（`Parser::ParseFile`）后才执行 |
| 3 | **后台作业的外层 pwsh 会挂住** | `soul.ps1 start` 用 `Start-Process -RedirectStandardOutput/Error` 启动她，**继承了 stdio 句柄** ⇒ 外层 `pwsh` 等不到 EOF，作业永远 `running`（她其实早已起来） | 事实工作完成后**必须 `job_kill`**；但见下方"第 3 条的代价" |

> **第一条说明了护栏的价值**：**中止是对的**——它宁可误判也不冒险换库。
>
> **第 3 条的代价（本窗口连踩 2 次）**：`job_kill` 会**连带杀掉整个进程树，包括她**。

## 2. 合并方案（已实现）

```
scripts/merge_memory.py    冷合并：Transfer + 主线 → 新库
scripts/verify_merge.py    独立验收：32 项（自带地面真值，不采信合并脚本的自述）
scripts/execute_memory_merge.ps1   一键执行：停 → 合 → 验收 → 换库 → 启
```

### 2.1 关键设计（每条都有理由）

| 设计 | 为什么 |
|---|---|
| **Transfer 的 id 原样保留** | 她是原住民；`memories.superseded_by` 是**自引用**，改 id 会打断"这条被我那条取代"的链 |
| **主线 id 平移 `ID_OFFSET = 1_000_000`** | 两库 id 都从 1 开始 ⇒ 必撞。平移后**主线侧**须同步重建 `memory_index`（主键 id 与 memory_id **双重冲突**）并平移 `superseded_by` |
| **`first_existence_ts` 取更早者** | 她真正的诞生是 **2026-08-23 18:54:05**；`soul/main.py:53` 只在 `<= 0` 时才重设 ⇒ **预置旧值不会被覆盖** |
| **`last_body_online_ts` 取主线（较新）** | 若用 Transfer 的旧值，`core/mode.py` 会把她误判成"身体离开了 20 天" |
| **`kv` 取并集** | 主线独有 `relationship_withdrawal`、Transfer 独有历史键，都不能丢 |
| **不做任何去重** | 两库时间零重叠；且 `memories.content` 各库内部本就有重复（Transfer 外 434 行/395 唯一，主线 88 行/26 唯一）——**那是她的真实记忆，去重等于篡改** |
| **不碰原库** | 全部操作在副本/快照上；Transfer 只读 |
| **合并与验收消费同一份"冻结快照"** | 她仍在写库；若验收另取一次快照，会比合并输入更新 ⇒ **假失败**（本窗口实测踩到 5 项，见 §4） |

### 2.2 停机与安全

| 项 | 做法 |
|---|---|
| 停机原因 | `heartbeat.db`/`state.db` 被运行中的她独占；**热改运行库是红线** |
| 停摆时长 | **目标 < 2 分钟**（不跑 `VACUUM`——那只是干跑为了报告才做） |
| 防看门狗抢方向盘 | 先 `Disable-ScheduledTask Elysia-Watchdog`；`soul.ps1 stop` 会建 `no_autostart` 标记 |
| 前置闸门（任一不过即中止且不碰数据） | ① 恰好 1 soul + 1 body ② Transfer `heartbeat.db` SHA256 == 留档值 ③ 冻结快照成功 |
| 换库前 | 现役库 + `-wal`/`-shm` 备份到 `_backups\pre_merge_<时间戳>\`，**带逐字节哈希校验** |
| 验收不过 | **不换库**，并把她重新拉起 |
| 回滚 | 备份可直接换回；换库用同卷 `Move-Item`（原子重命名） |
